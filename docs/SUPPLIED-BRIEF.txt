KERALA ROUTES — V1: FIRST JOURNEY
Main goal: prove that this works:
Real player drives a Kerala bus → real players wait at stops → board the bus → travel together → get off → walk around → complete missions → catch another real-player bus.

For V1, don't try to reproduce Kozhikode at 1:1 scale. We use real place names and their general geographical relationship, but compress distances to approximately 1:5–1:8 scale. That makes the browser game small enough for normal PCs and phones.

16. Multiplayer architecture
This part is very important.
The server must own the important game state.
Don't let every browser decide everything.
Server holds:
Player ID
Player position
Player role
Bus driver
Bus position
Bus passengers
Current route
Stops
Mission completion

Network:
PLAYER A
   ↓
input
   ↓
SERVER
   ↓
authoritative state
   ↓
PLAYER A
PLAYER B
PLAYER C
PLAYER D

Client sends:
accelerate
brake
steer
board
exit
openDoor

Server checks it and broadcasts the result.
This prevents one player from accidentally controlling another driver's bus.
17. Network rate
Do not send 60 network messages every second.
Use approximately:
Game rendering:
60 FPS

Player network:
10–15 updates/sec

Bus network:
15–20 updates/sec

Other clients interpolate smoothly between updates.
Example:
Server bus position:

A -------- B

Client renders:

A -> -> -> -> B

instead of jumping.

19. Build it in this exact order
Do not tell Astra to generate the entire game in one response. Even a strong coding model will produce a mess if we ask it to simultaneously create the map, multiplayer, vehicle physics, missions and UI.
Build these stages in order:
1. Project foundation — Create Vite + TypeScript + Babylon.js client and Node/Socket.IO server. Get a green ground plane and one controllable player running.
2. Walking character — WASD, third-person camera, collision, sprint, mobile joystick.
3. Prototype Kozhikode map — roads, KSRTC terminal, Mananchira, beach, Medical College, Kunnamangalam and Kattangal represented initially by simple buildings and labels.
4. One bus — steering, acceleration, braking, camera, wheels, doors and driver seat.
5. Multiplayer players — two browsers can join and see one another walking.
6. Multiplayer bus — one player becomes driver; everyone else sees the bus moving smoothly.
7. Passenger boarding — player enters/leaves bus and moves correctly with it.
8. Stops — stop zones, Malayalam/English names, arrival detection and next-stop UI.
9. Second bus — allow two simultaneous real drivers.
10. Routes — City/Beach route and Kattangal route.
11. Exploration — allow passengers to get off and walk around mission zones.
12. Missions + Kerala Points — implement the 8 V1 missions.
13. Weather — clear/cloud/rain/evening.
14. AI traffic — simple waypoint traffic.
15. Mobile UI — touch joystick, driving controls and responsive menus.
16. Supabase save system — save Kerala Points, journal and completed missions.
17. Optimisation — GLB compression, instancing, culling and low/mobile graphics settings.
18. Deployment — Cloudflare Pages + Render + Supabase.
19. Multiplayer test — test 2 players, then 4, then 8, then 12. Don't immediately test 30.
20. V1 release — only after driver/passenger switching, reconnects, boarding and bus synchronization are stable.
